# Sprout 2026.11.19

第三个公开版本。上一版补齐了 MCP 工具与技能；这一版补上 JSON-RPC 入口（`sprout serve`）、子代理与会话分支，MCP 也从「只有工具」做到全协议（Resources、Prompts、Elicitation、MRTR、Sampling、OAuth），并让 `sprout update` 真正能自己换上新版本。

## 本版新增

### JSON-RPC（`sprout serve`）

`internal/rpc` 实现，TUI / `sprout run` / 编辑器插件共用同一套内核、工具与会话记录。一行一条消息（UTF-8 JSON），stdout 只有协议消息，日志照旧写数据目录。

- `turn/start`、`turn/cancel`、`event` / `notice` 通知：流式正文、思维链、工具进度与用量都以事件推出。
- 会话：`session/new`、`session/list`、`session/resume`（返回重放事件）、`session/tree`、`session/navigate`、`session/rename`、`session/delete`、`session/compact`（可取消）。
- 模型与思考程度：`model/list`、`model/switch`、`effort/list`、`effort/set`，一轮进行中也能改档位。
- 服务端请求：`mcp/elicit`、`mcp/sample`，把 MCP 的 elicitation / sampling 转给客户端；`initialize` 时声明了对应能力才会发。
- stdin 关闭或 `shutdown` 取消进行中的一轮，最多等 5 秒收尾后退出。协议细节见 `docs/rpc.md`。

### 子代理（`agent` 工具）

主代理可以把一块独立工作交给子代理做，子代理有自己的上下文，只把最终报告交回。

- 同步、只有一层：子代理的工具表里永远没有 `agent`；同一次回复里的多个 `agent` 调用并行执行。
- 内置 `general`（主代理的全部工具）与 `explore`（只读倾向，只给 `read` / `bash` / `powershell`，只读靠提示词约束，**不是沙箱**）。
- 自定义类型：`<数据目录>/agents/*.md` 与 `<工作目录>/.sprout/agents/*.md`，项目级优先。frontmatter 可写 `tools`（支持通配）、`model`、`effort`。
- 子代理过程单独记在 `<会话名>.agents/<call id>.jsonl`；主会话只记 `subagent_usage`，恢复后花费不丢。
- 界面上的子代理卡片显示进度与用法，`sprout serve` 以 `subagent` 事件转发。见 `docs/subagents.md`。

### 会话分支与 `/tree`

一个会话可以分叉：在某轮之后继续追问、或回去改问那一轮，原对话随时能切回。

- `/branch` 从当前轮开新分支继续；`/tree` 打开树形面板，`Enter` 切到选中那一轮之后，`e` 改问那一轮（原提问放回输入框）。
- 所有分支存在同一个会话文件里，切换只追加一条 `branch` 记录，恢复时会重放出当前分支的样子。
- RPC 对应 `session/tree` 与 `session/navigate`。规则见 `docs/session-format.md`「分支与会话树」。

### MCP 补齐

- **Resources**：`resources/list`、`resources/templates/list`、`resources/read`，模型可通过工具读取。
- **Prompts**：`prompts/list`、`prompts/get`，注册为 `list_prompts` / `get_prompt` 工具。
- **Elicitation**：服务端发起的 `elicitation/create`（form 模式），TUI 弹表单填写；`sprout serve` 转发给客户端。
- **MRTR**：`tools/call`、`resources/read`、`prompts/get` 返回 `input_required` 时补充输入后重发，最多 8 轮。
- **Sampling**：服务端请求生成，用户确认后用当前模型生成，结果回给服务端。
- **OAuth**：`sprout mcp login` / `logout`，PKCE、受保护资源与授权服务器元数据发现、动态客户端注册、浏览器授权与回环回调、令牌刷新。令牌只存 `mcp-auth.json`（0600），不进日志。见 `docs/mcp.md`。
- **工具结果里的图片**转成图片块交给模型，支持视觉的模型能直接看图。
- **工具列表缓存** `mcp-tools.json`：有效期取服务端 `ttlMs`（缺省 10 分钟），按连接目标指纹失效；收到 `notifications/tools/list_changed` 后台重新列工具并热接入，启动少一轮 `tools/list`。

### 自动更新

`sprout update` 从「只检查」变成「能自己换」：

- 读 GitHub Releases 的最新发布，下载本平台压缩包与 `SHA256SUMS.txt`，校验、解压、用 `--version` 试运行通过后才替换当前程序；任一步失败都不动原程序。
- Windows 上正在运行的 `sprout.exe` 不能覆盖，先改名成 `.old`，下次启动时清理。
- TUI 里是 `/update`，启动时也会在后台查一次，有新版本才在对话区提示；`--check` 只报告。

### 状态栏与界面

- 状态栏改为可配置布局（数据目录 `statusline.jsonc`）：项目名、模型、轮次、耗时、token、花费、上下文占用、MCP 与技能数、进程内存、输出速度、Git 分支与改动数、Windows 负载等，行内项与顺序都能改；内置项与颜色见 `docs/` 与 `statusline.example.jsonc`。
- 每轮回答下方一行淡色统计：`耗时 · 首字 · token/s · 输入 · 输出 · 缓存 · 合计`，只算主对话这一轮的模型调用。
- 生成中提交的消息排队发送，不会再被丢掉；报错与重试提示分色显示。
- 记住上次选择的模型与思考档位（`settings.jsonc`，旧的 `state.json` 自动改名沿用）。

### 上下文与稳定性

- 旧工具输出按工具类型裁剪（策略版本 2）：`read` 只留开头并提示可重读，`agent` 开头结尾多留，`mcp__*` 留开头，shell 与外部命令留开头和结尾；旧会话仍按版本 1 重放。`/compact -k` 保留最近一轮原文，只压缩它之前的对话。
- 工具可声明「不可并行」：`write`、`edit`、`delete` 独占执行（等前面的结束、执行时不启动别的），同批里改同一个文件不会互相覆盖；`tools.jsonc` 的 `parallel` 可覆盖。
- 技能正文不参与旧输出裁剪；Responses 回传 reasoning 条目、Gemini 回传 `thoughtSignature`，思考链跨轮次保留。
- 重试改为 1s 到 64s 的指数退避（共 7 次，不加抖动），仍听 `Retry-After`。
- `models.jsonc` 改动后 TUI 自动重新读取，当前模型的设置变了就在空闲时重建 agent、保留对话；写错时继续用旧配置并提示。
- 系统提示词强调「想清楚下一步就动手」，大文件提示分段写。

## 修复

- 首字延迟按每次模型调用单独计时，不再把多调用的一轮算成一个长首字。
- 状态栏恢复竖线分隔；不再逐条提示被 `scanAgents` 挡住的技能。
- 状态栏各行按列对齐的实现引入回归后已撤销，改为按参考样式重排。
- 会话路径文档改为以实际实现为准（`sessions/--<cwd slug>--/...`）。

## 安装

解压后即可用。首次运行会在程序所在目录的 `data/.sprout/` 生成带注释的 `models.jsonc`，填入 API Key（或设置对应环境变量，如 `DEEPSEEK_API_KEY`）后重启即可。

Windows 上双击 `sprout.exe` 进终端界面；在 TUI 里执行 `/install-sprout` 可注册成全局 `sprout` 命令（改用户 PATH），`/uninstall-sprout` 卸载。

从上一版升级：执行 `sprout update` 即可自动换上新版本；也可以直接替换可执行文件，数据目录（配置、会话、日志）原样保留，`state.json` 会自动改名为 `settings.jsonc`。

## 已知限制

- **没有权限模块**：默认完全权限，模型可以直接执行命令、读写文件，子代理同理。工具子进程继承环境变量（包括 API Key）。请只在你能接受这个前提的环境里使用。
- **没有 WebUI**：`sprout web` 尚未实现。
- **JSON-RPC、子代理、OAuth 未在真实环境验证**：RPC 只有单元与端到端测试，没有用真实客户端手工跑过；子代理只有 `httptest` 端到端测试，TUI 卡片没在真实终端里看过；OAuth 没对接过真实服务商、没用真实浏览器跑过，不支持 CIMD。
- **后台子代理没有**：一次 `agent` 调用必须等子代理结束；子代理换模型时花费仍按主模型单价折算。
- **项目级技能与子代理定义是提示注入面**：`.agents/skills/`、`.sprout/skills/`、`.sprout/agents/*.md` 的内容会进上下文，没有信任门槛，只建议在可信仓库里使用。
- **`models.jsonc` 只在 TUI 里热加载**：`sprout run`、`sprout serve` 和缺 API Key 启动时仍要重启。
- **macOS / Linux / Termux 只验证到能编译**：`bash` 探测、进程组终止、剪贴板等 Unix 路径只有单元测试，没有在真实系统上手工跑过。
- **OpenAI 官方服务未验证**：Chat 与 Responses 都只在 DeepSeek 上跑过真实对话；带 reasoning 的 gpt-5 / o 系列行为可能不同。
- **并行工具靠提示词约束**：同一批调用互相看不到结果，有依赖的命令要分回合；`write` / `edit` / `delete` 已独占，shell 命令之间仍然并行。
- **花费只用基础价**：忽略 models.dev 的分档价（`tiers`、`context_over_200k`），也没有和真实账单核对过；没有价格时显示 `—`。
- **`go test -race` 未跑**：开发机没有 CGO 工具链。
- **macOS 未签名、未公证**：首次运行需要右键打开，或 `xattr -d com.apple.quarantine sprout`。
- **会话与日志只增不减**：`sessions/`、`logs/` 没有清理或轮转。
