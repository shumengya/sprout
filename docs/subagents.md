# 子代理

主代理通过内置工具 `agent` 把一块独立的工作交给子代理。子代理是一个全新的 `agent.Agent`：它有自己的上下文，看不到主对话，做完只把一份文字报告交回，报告就是这次工具调用的结果。

代码在 `internal/agent/subagent`（类型定义与 `agent` 工具）和 `cmd/sprout/subagent.go`（装配：模型、系统提示词、记录文件）。

## 1. 行为

- **一层**：子代理的工具表里永远没有 `agent`，所以它不能再派子代理。
- **前台或后台**：默认一次调用要等子代理结束才返回。`agent` 工具声明了可后台（见 `docs/tools.md`「后台执行」），模型在参数里写 `run_in_background: true` 时，调用当场返回任务编号，主代理接着做别的，子代理的报告结束后作为一条用户消息自动送达。后台子代理属于发起它的那一轮：主代理答完了它还没结束，这一轮就等它。`tools.jsonc` 里给 `agent` 写 `"background": false` 可以关掉这种用法。
- **并行**：同一次回复里的多个 `agent` 调用，和其他工具一样并行执行（上限 `MaxParallelTools`，默认 4）。
- **独立上下文**：子代理只收到 `prompt` 这一条用户消息。它的系统提示词按主代理同一份 `SYSTEMPROMPT.md` 渲染（工具列表换成子代理自己的），带上 `AGENTS.md` 与技能目录，末尾追加「子代理」一节（`subagent.SystemSection`）说明身份与报告要求，再接上该类型的角色说明。
- **报告**：子代理最后一条不带工具调用的回复。超过 50KB 截断。子代理出错、被长度上限截断、没有给出文字时，结果的退出码为 1，正文写明原因，并附上它停下前的最后输出。这些都不算工具失败，由主代理自己决定下一步。
- **取消**：取消主代理的这一轮，子代理随 ctx 一起取消，后台子代理也一样；主代理这一轮出错或超过步数结束时，后台子代理被终止。
- **自动压缩、重试**：子代理和主代理一样会自动压缩上下文、自动重试，它的 `contextWindow` 取自它所用的模型。
- **不交互**：子代理不能向用户提问。MCP 的 elicitation / sampling 仍然走主界面，因为子代理用的是同一批 MCP 工具。

## 2. 工具参数

```json
{
  "description": "3 到 10 个字的标题，显示在界面上",
  "prompt": "完整任务说明",
  "agent": "子代理类型，省略为 general",
  "run_in_background": false
}
```

`run_in_background` 不是 `agent` 工具自己的参数，是内核给所有可后台工具加的，执行前去掉。

`agent` 的取值是 schema 里的 `enum`，工具描述中列出每种类型的说明和可用工具。

## 3. 子代理类型

| 来源 | 位置 | 优先级 |
| --- | --- | --- |
| 内置 | `general`、`explore` | 最低 |
| 用户 | `<数据目录>/agents/*.md` | 中 |
| 项目 | `<工作目录>/.sprout/agents/*.md` | 最高 |

同名时优先级高的整个替换低的，所以可以写一个 `explore.md` 换掉内置的 `explore`，比如让它用更便宜的模型。

- **general**：主代理的全部工具（`agent` 除外）。
- **explore**：只有 `read`、`bash`、`powershell`，角色说明要求只读。shell 本身仍能写文件，只读靠提示词约束，**不是沙箱**。

### 定义文件

每种类型一个 Markdown 文件，开头是 YAML frontmatter，正文是角色说明：

```markdown
---
name: reviewer            # 可省略，默认取文件名；只用小写字母、数字和单个 - 或 _，最长 64
description: 审查代码改动，只报告真正的 bug   # 必填：主代理靠它判断什么时候派
tools: [read, bash, mcp__github__*]          # 可省略，省略表示主代理的全部工具；也可写成 "read, bash"
model: deepseek/deepseek-pro                 # 可省略，models.jsonc 里的 provider/model；inherit 等同省略
effort: high                                 # 可省略，该模型声明过的思考档位
---
只看 diff 涉及的代码，不改文件。每个问题给出 路径:行号 和触发条件。
```

- 目录不递归，`README.md` 跳过。目录不存在不算问题。
- 写错的文件只跳过它，原因在启动提示里列出。`model` 引用不存在时也在启动时提示；这种类型照样列给主代理，但派出时会失败，失败原因作为工具结果交回主代理。
- `tools` 支持 `path.Match` 通配，每次调用时才从主代理的工具表里筛选，所以外部工具和后台连上的 MCP 工具同样能匹配。写了 `tools` 但一个都匹配不上时，这次调用失败。`tools: []` 表示一个工具都不给。
- 修改后需要重启 sprout 才会生效。

### 模型与思考档位

- 不写 `model`（或与主代理当前模型相同）：沿用主代理当前的模型和思考档位，`/model`、`/effort` 切换后派出的子代理跟着变。
- 写了别的模型：用该模型的 API Key 与默认档位。Key 缺失时派出失败。
- 写了 `effort`：用这个档位。当前模型没有这个档位时派出失败。
- 模型在 `models.jsonc` 里设了 `tools: false` 时，子代理不下发任何工具。

## 4. 事件与界面

子代理的事件经 `tool.Call.Emit` 交给内核，由主 goroutine 包成 `event.Subagent{CallID, Agent, Event}` 发给 sink，落在这次调用的 `tool.requested` 与 `tool.finished` 之间；后台子代理的事件落在 `tool.finished`（`Background` 为 true）与 `background.finished` 之间，Emit 不阻塞，事件先排队，主 goroutine 在下一个空当转发。流式增量不转发（见 `docs/events.md`）。

- **TUI**：`agent` 工具卡片下面显示「子代理 explore · N 次工具调用 · 输出 Nk token」，并列出子代理的工具调用（运行中只列最近 4 次，点击卡片展开全部），结束后显示报告。后台子代理的卡片显示「后台运行中…」，结束时卡片换成报告，对话区末尾补一行「后台任务已结束：…」；主代理答完、只剩后台任务时状态写「等待 N 个后台任务」。子代理的用量计入状态栏的输入、输出、缓存与花费，但不计入上下文占用和输出速度。
- **`sprout run`**：子代理的工具调用与出错以 `  │ <类型> · [工具] 命令` 的形式写到 stderr。后台调用先写 `  └ 已转入后台`，结束时写 `[agent] 后台任务结束（<id>）：…`。
- **JSON-RPC**：推送 `kind: "subagent"` 的 `event` 通知，内层事件放在 `event` 字段（见 `docs/rpc.md`）。

## 5. 记录

- 子代理的完整过程记在 `<会话名>.agents/<call id>.jsonl`，格式与普通会话相同（`session` 头里多一个 `agent` 字段），可以用 `session.Load` 读出来。它在会话的 `.agents/` 目录里，不出现在 `/resume` 列表里，删除会话时一起删除。
- 主会话里只多一类 `subagent_usage` 记录，恢复会话后花费仍然对得上。恢复时卡片只显示报告，不重放子代理的过程。
- 细节见 `docs/session-format.md`。

## 6. 已知限制

- 不能给运行中的子代理追加消息，也不能单独取消某一个后台子代理（只能取消整轮）。
- 后台子代理不能跨轮：一轮要等它结束才收尾。等待期间可以继续排队发消息，但界面一直处于“生成中”，`/model` 等要等这一轮结束。
- 子代理用了别的模型时，TUI 仍按主模型的单价折算它的花费（界面只知道当前模型的价格）。
- 并行的多个能改文件的子代理之间没有互斥：`write` / `edit` / `delete` 只在同一个 agent 的同一批调用里独占执行。后台子代理和主代理之后的调用同样没有互斥。工具描述要求主代理给它们不重叠的范围。
- 项目级定义（`.sprout/agents/`）和项目级技能一样是提示注入面：克隆来的陌生仓库可以带着自己的子代理定义。
